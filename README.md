# VOID 插件

**配合 [VOID 主题](https://github.com/mikusaa/Typecho-Theme-VOID) 使用**

使用方法：下载本插件后，部署到 Typecho 插件目录时请将文件夹名称改为 `VOID`，然后在后台启用。

## 功能概览

- 文章点赞、评论赞踩，以及后台互动记录查看
- 文章浏览量统计，可供主题前台直接读取显示
- 文章与页面字数统计，并支持在前台模板中调用
- 后台评论列表显示评论 IP 与归属地
- 图片尺寸解析与历史 `#vwid` / `#vhei` 标记兼容
- 1.4.2 新增：发布文章或页面后自动维护首页封面的 `bannerMeta` 原始宽高元数据
- 插件设置中可调整“单次图片处理数量上限”
- 1.4.1 新增：后台写作统计和互动记录页面可跟随 DarkMode 切换夜间样式
- 1.4 新增：后台编辑器实时统计面板，可在写文章或页面时实时显示字数、图片数、标签数
- 1.4 升级：评论 IP 定位已切换为 `ip2region xdb`，支持 IPv4 与 IPv6
- 1.4 升级：UA 识别范围更完整，后台互动页可更准确显示访客浏览器与系统信息

## 后台夜间模式

从 1.4.1 开始，VOID 的后台写作统计面板和“互动”记录页面支持夜间样式。该功能可与 [DarkMode](https://github.com/mikusaa/Typecho-Plugin-DarkMode) 配合使用，但 DarkMode 不是安装 VOID 的必要依赖。

- 安装并启用 DarkMode 后，VOID 会跟随其日间、夜间和设备模式，并在切换时立即更新外观。
- 未安装 DarkMode 时，VOID 保持 Typecho 原生浅色后台，不会自行读取设备主题，也不会显示额外的外观开关。
- VOID 不读取 DarkMode 的浏览器存储或 PHP 类，只根据页面上的 `html[data-typecho-theme="dark"]` 最终状态启用夜间样式。
- 夜间样式仅作用于 VOID 自己生成的后台组件，不修改 Typecho 其他后台页面，也不影响博客前台和 VOID 主题样式。

## 关于 IP 数据库的更新

VOID 当前已换用 [ip2region](https://github.com/lionsoul2014/ip2region) 提供的 `.xdb` 数据库文件，插件不内置数据库检查或一键更新能力。若本插件不再更新，后续数据库维护需手动。

> 当前仓库内置数据库对应 `ip2region v3.14.0`，数据库文件可从 ip2region 官方仓库的 Release 页面，或仓库 `data/` 目录中获取

更新步骤：

1. 下载最新的 `ip2region_v4.xdb` 与 `ip2region_v6.xdb`
2. 分别替换插件目录中的 `libs/data/ip2region/data/ip2region_v4.xdb` 与 `libs/data/ip2region/data/ip2region_v6.xdb`
3. 保持文件名不变，并确保 IPv4 与 IPv6 文件成对更新
4. 替换完成后，建议在后台停用并重新启用插件一次，以触发启用阶段的数据库校验

注意事项：

- 若数据库文件缺失、损坏，或 IPv4 / IPv6 文件类型不匹配，插件会在启用时给出明确错误
- 如果插件被重新安装，或被新版插件包直接覆盖，上述内置数据库文件也可能被一并覆盖，需要重新手动替换

## 关于图片尺寸解析

### 正文图片

- 插件会在内容发布后尝试为文章中的图片补充尺寸信息，以便主题前端更稳定地预留图片占位
- 历史文章中已经写入的 `#vwid` / `#vhei` 标记会继续保留并生效
- 插件设置中的“单次图片处理数量上限”用于控制单次处理的图片数量，默认值为 `10`
- 不建议将该值设置得过大，因为图片尺寸获取仍受外部图床响应速度影响，数值过高可能导致请求超时

### 首页封面

- 从 1.4.2 开始，插件会在同一发布流程的自定义字段保存完成后读取 `banner`，并补全独立的 `bannerMeta`；有效同源元数据会直接跳过，空封面会清理旧元数据，解析失败不会阻止发布
- `bannerMeta` 只记录来源 URL 和原始宽高。插件不会修改用户填写的封面 URL，也不会调整图片像素、编码、质量或文件内容
- 插件激活或升级时不会自动扫描历史封面。可从“控制台 → 插件 → VOID 设置 → 封面尺寸元数据”进入确认状态，再通过带安全 token 的 POST 操作按 `cid` 从新到旧分批回填
- 普通历史回填会跳过来源匹配且元数据有效的内容，不重复请求对应封面。单张失败只计入本批失败数，不会阻塞后续内容或批次游标
- “从最新内容重新检测”会忽略已有有效元数据，重新获取实际尺寸并覆盖写回；只要获取成功便计为成功，即使尺寸没有变化。该操作主要用于同一 URL 原地替换图片或重试失败项

## 兼容性说明

- 当前源码同时保留了对 Typecho 1.2 与 1.3 的兼容处理
- 插件目前仅支持 MySQL 数据库
- 运行插件前，请确保 PHP 已启用 `OpenSSL` 与 `DOM` 扩展
